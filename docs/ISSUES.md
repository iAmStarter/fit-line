## 2026-07-04 · Phase 5 · image-reject dispute auto-offer vs frozen Phase-1 router contract (deferred)
- **symptom:** wiring `bumpFailCount` into `handleImageMessage`'s reject path (to auto-offer "แจ้งแอดมิน" at fail≥3) fails `test/phase-1/router.spec.ts › reject path (no stash)` — it asserts `putSpy).not.toHaveBeenCalled()` + `cacheStore.size).toBe(0)` (a reject writes **nothing** to CacheService). `bumpFailCount` persists the fail counter via `CacheService.put(fc:<userId>:<activity>, …)`, which trips both.
- **root cause:** cross-phase conflict, not internal contradiction. router.spec was frozen at Phase 1, when the reject path did zero cache writes; it mocks the cache-writing collaborators that existed then (`rateLimit`) but could not mock Phase-5's `disputeGuard` (didn't exist). disputeGuard.spec (Phase 5) REQUIRES `bumpFailCount` to call `CacheService.put` with the `fc:` key. The two frozen contracts cannot both hold on that single code path, and **no test drives the image-reject→auto-offer integration** (only the builder `buildRejectCard({disputeMessageId})`, the `disputeGuard` unit, and the postback dispute branch are covered).
- **fix:** RESOLVED. The auto-offer is now wired into `handleImageMessage`'s post-OCR reject branch: `bumpFailCount(userId, metrics.activityType)` bumps the per-(user, activity) counter (key `fc:<userId>:<activityType||unknown>`) and `shouldOfferDispute(failCount)` gates whether `buildRejectCard(…, { disputeMessageId })` attaches the "แจ้งแอดมิน" quick reply keyed to this messageId. The bump fires ONLY on post-OCR RULE rejects — pre-OCR block paths (rate-limit / duplicate) return before it. The cross-phase router-contract conflict was cleared by the test-author, who re-froze `router.spec.ts` to `jest.mock('../../src/rules/disputeGuard')` (line 71), so the reject-path zero-cache-write assertions still hold while the real counter runs elsewhere. New integration coverage: `test/phase-5/imageRejectDispute.spec.ts` (4 assertions: 1st/2nd no affordance, 3rd carries `action=dispute&mid=m3` as a message-level quick reply, per-activity + per-user counters independent).
- **status:** RESOLVED — FULL suite 197/197 green; tsc/eslint/prettier/build clean.
